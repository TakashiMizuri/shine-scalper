# Shine Scalper — спецификация v0.1

> Документ фиксирует согласованные требования к боту автоматизированной торговли на Bybit (USDT-M futures).  
> Версия: **0.1** · Дата: **2026-06-04** · Статус: **проектирование / pre-MVP**

---

## 1. Цель проекта

Разработать систему для **скальперской / импульсной** торговли на криптофьючерсах с фокусом на **пробои уровней**. Уровни определяются на **5m**, исполнение и наблюдение — в **реальном времени** (секунды–минуты). Система должна поддержать **paper-торговлю**, затем **live**, и предоставлять **веб-дашборд** с живым графиком, уровнями и отметками сделок.

## 3. Стратегия (MVP)

### 3.1. Режим торговли (v0.1)

- **Фокус: пробои уровней** (continuation через зону сопротивления / поддержки).
- Вход **не по close 5m** — слишком медленно для целевого поведения рынка.
- Логика входа (концепт): цена **плавно подходит** к зоне уровня, **находится в зоне** — вход в сторону **пробоя** (импульс через уровень).

### 3.2. Определение «уровня»

**Уровень** — не точная линия, а **ценовая зона**, к которой за заданный период цена многократно подходила и **отскакивала** (разворачивалась).

| Параметр | Значение (черновик, подлежит калибровке) |
|----------|---------------------------------------------|
| Таймфрейм построения уровней | **5m** |
| Окно истории | **~48 часов (2 дня)** |
| Представление | **Зона** `center ± width%` (ширина — настраиваемый параметр) |
| Сила уровня | Минимум **N касаний** зоны с отскоком за окно (N — конфиг) |
| Отскок (формализация) | Касание зоны + **close** свечи уходит от зоны в сторону разворота (направление зависит от типа уровня: support / resistance) |
| Актуальность | Опционально: последнее касание не старше **X часов** |
| Инвалидация | После подтверждённого **пробоя** (правило уточняется в signal engine): уровень снимается или переводится в режим S/R flip (post-MVP) |

### 3.3. Сигнал входа (пробой)

Компоненты сигнала (все пороги — **конфигурируемые**, значения по умолчанию задаются при реализации):

1. **Активный уровень** — зона из детектора уровней (5m / 48h).
2. **Подход к уровню** — сужение движения к зоне за окно **N минут** (на тиках / 1m).
3. **«На уровне»** — last price в зоне не менее **T секунд** или **K тиков** (уточнить при бэктесте/paper).
4. **Пробой** — импульс **через** зону (скорость изменения цены, объём на 1m / агрегированные тики — уточнить).
5. **Направление** — long при пробое resistance вверх, short при пробое support вниз (симметрично).

**Фильтры (рекомендуемые для v0.1):**

- Лимит **открытых позиций** по символу / глобально.
- **Daily loss limit** (процент от депозита — конфиг).
- Проверка **спреда** и минимальной **ликвидности** (для SOL — мягче, для альтов позже — жёстче).
- Учёт **funding** (опционально: не открывать за N минут до funding).

### 3.4. Стоп-лосс (SL)

- Точное правило **не зафиксировано** — требуется **A/B в paper**.
- Кандидаты для тестирования:
  - **За противоположной границей зоны уровня**;
  - **ATR-множитель** от 5m;
  - Комбинация (максимум из двух для long / минимум для short).

В логах paper каждая сделка должна сохранять **вариант SL**, чтобы сравнить expectancy.

### 3.5. Тейк-профит (TP) и RR

- **Частичное постепенное закрытие** позиции.
- Ориентир для частичных фиксаций: **ближайшие другие уровни** (следующие зоны support/resistance из того же детектора).
- Остаток позиции — **трейлинг** или выход на дальнем уровне / по правилу runner (уточнить в v0.2).
- Целевая экономика стратегии: **высокий RR на хвосте распределения** (примеры из практики трейдеров: 1:15, 1:30 на отдельных сделках), при этом **большинство сделок** могут закрываться раньше; оценивать **expectancy**, **profit factor**, влияние **комиссий и funding**, а не средний RR одной сделки.

### 3.6. Риск-менеджмент

| Правило | Значение |
|---------|----------|
| Риск на сделку | **2%** equity |
| Плечо | **10x** (ориентир; фактическое — настройка аккаунта Bybit) |
| Размер позиции | Из риска 2% и дистанции до SL (стандартная формула) |
| Несколько позиций | **Разрешено** (несколько монет позже; на MVP — в основном одна позиция по SOL, но архитектура multi-position) |
| Корреляция (post-MVP) | Лимит суммарной экспозиции по группе альтов |

## 4. Roadmap стратегии (вне MVP, в документе)

Следующие режимы **не реализуются в v0.1**, но закладываются в архитектуру (`ISignalEngine`, режимы стратегии):

| Режим | Описание |
|-------|----------|
| **Отскок (fade)** | Вход от границы зоны **против** пробоя при подтверждении разворота |
| **Стакан: отскок от объёма** | Крупные лимитные заявки / кластеры ликвидности как микро-уровень |
| **Стакан: пробой объёма** | Исчезновение / съедание крупного уровня в стакане как триггер |
| **S/R flip** | Бывший resistance → support после пробоя |

Для стакана потребуется **order book WebSocket** (L2), отдельный модуль агрегации и более жёсткие требования к latency.

## 5. Режимы работы бота

### 5.1. Paper trading

- Тот же пайплайн: market data → levels → signals → risk → **исполнение в симуляторе**.
- Fills моделируются по **last / mid** с настраиваемым **slippage**.
- Учитываются **комиссии taker/maker** (конфиг под Bybit).
- Все сделки, сигналы и отклонённые входы пишутся в БД для анализа на дашборде.

### 5.2. Live trading

- Переключение через конфиг (`TradingMode: Paper | Live`).
- Реальные ордера через **Bybit API V5** (unified trading).
- Отдельные API-ключи с минимальными правами; рекомендуется **субаккаунт**.

## 11. Метрики успеха (paper-фаза)

Перед live ориентиры для оценки:

| Метрика | Зачем |
|---------|--------|
| Expectancy ($/сделку) | Жива ли стратегия после комиссий |
| Profit factor | Отношение gross profit / gross loss |
| Win rate + avg win / avg loss | Баланс с высоким RR на хвосте |
| Max drawdown | Риск для 2% на сделку |
| Доля runner-сделок (RR > 5) | Проверка гипотезы 1:15+ |
| Slippage vs модель | Реализм paper |

**Минимальный срок paper:** 2–4 недели непрерывной работы с полным логированием (рекомендация).

## 12. Безопасность и эксплуатация

- API-ключи только на VPS, **не в репозитории** (secrets / env).
- IP whitelist на Bybit, где возможно.
- Логи без секретов; ротация логов.
- Kill-switch: остановка новых входов + опционально flatten (ручная кнопка на дашборде — post-MVP).
- Мониторинг: heartbeat сервиса, алерт при обрыве WS (post-MVP: Telegram).

## 15. Глоссарий

| Термин | Значение |
|--------|----------|
| **Уровень** | Зона цены с множественными отскоками за ~48h на 5m |
| **Пробой** | Импульс цены через зону в сторону продолжения движения |
| **Paper** | Симуляция исполнения без реальных ордеров |
| **Runner** | Сделка с большим RR, удерживаемая до дальнего уровня / трейла |
| **Зона** | `center ± width%`, не одна цена |
